# scavengesurvive-mta — conventions

Scavenge & Survive ported to MTA:SA 1.6 (Lua 5.1) with MariaDB 13.0 (12.2 also verified). Design spec:
`docs/superpowers/specs/2026-09-27-scavengesurvive-mta-port-design.md` (Appendix A = upstream behaviour, Appendix B = verified MTA facts).

## Layout

- `resources/[scavengesurvive]/<name>/` — one MTA resource per domain, **no prefix**. Inside: `meta.xml`, `shared/`, `server/`, `client/`.
- `lib` resource serves modules: `local db = loadstring(exports.lib:getModule("db"), "=lib/db.lua")()`.
- `sql/schema.sql` (generated by `python -m tools.sqltool --db scavengesurvive dump`): every table as `CREATE TABLE IF NOT
  EXISTS`, then a `DELIMITER //` block with every procedure, function, trigger and event as `CREATE OR REPLACE` (the
  `items` triggers keep `world_items_pos` in step, so nothing writes that table by hand); `sql/seed/*.sql` (generated).
- `tools/convert/*.py` — deterministic converters from `../ScavengeSurvive` into `data/generated/` + `sql/seed/`;
  `maps.py` writes `maps/data/<ZONE>.lua`, `maps/data/zones.lua`, `maps/meta.xml` and `docs/maps-census.md` (all generated, all committed).
- `tests/lua` (busted), `tests/tools` (pytest), `tests/sql` (pytest + live MariaDB database `scavengesurvive_test`).
- `docs/runbooks/` (operations), `docs/staff-commands.md` (staff parity table), `docs/reviews/<date>-*.md` (live checks).

## Rules

- Events: names are `<subject><PastTenseVerb>` camelCase with no `on`, `onClient` or `Request` prefix (e.g. `itemCreated`, `inventoryOpened`, `itemPickupRequested`); direction comes from registration, not the name. Client to server events are registered through `net.handler(...)` (`addEvent(name, true)`), server to client events with `addEvent(name, true)` on the client side, purely local events with `false` (e.g. `uiListActionSelected`, `playerAuthenticated`). Each resource declares every event it triggers or handles in `shared/events.lua`, grouped by direction. MTA event names are global, so every name carries its own subject.
- Remote handlers are registered through `net.handler(...)` from `lib`; trust only the `client` global.
- DB: identical connection string in every resource (`lib/modules/db.lua`), `batch=0`; anything touching more than one row is a stored procedure returning `SELECT ok, code, payload`.
  Each autocommitted write costs ~2 ms (the commit's log flush), a read ~0.1 ms: batch repeated writes into one
  procedure call taking a JSON array (`JSON_TABLE`, see `loot_roll`, `character_flush`) instead of one call per row.
- No migration or procedure files: tables, procedures, functions, triggers and events are all changed live (DDL or
  `CREATE OR REPLACE …` straight against `scavengesurvive`), then `dump` and commit the regenerated `sql/schema.sql`
  (never hand-edit it); one-off data fixes run directly, no file (`docs/runbooks/change-database-schema.md`).
- DDL on a system-versioned table (`accounts`, `items`, `bans`) runs `SET SESSION system_versioning_alter_history = KEEP;`
  first in the same session (MariaDB error 4119 otherwise).
- Staff tooling lives in the `staff` resource (levels from `accounts.admin_level`, every action in `staff_actions`); a
  new privileged command goes through `ctx.command({ name, level, fn })` there, never into `dev`. Bans are MariaDB rows
  enforced by `auth` on join; never `banPlayer`/`addBan`.
- Stored procedures: `SET TRANSACTION ISOLATION LEVEL READ COMMITTED;` before every `START TRANSACTION` (MariaDB 12 deadlocks/`1020` under REPEATABLE READ with `FOR UPDATE` races); numbers in `JSON_OBJECT` payloads are wrapped in `CAST(x AS SIGNED)` (procedure variables serialise as strings otherwise); compare possibly-NULL ownership columns with `<=>`.
- DB rows: NULL arrives as `false`; DECIMAL as string; FLOAT is 32-bit; never select raw POINT (`ST_X/ST_Y`); every `?` in SQL text is a placeholder (`CHAR(63)` for a literal).
- Client never calls `setElementData`. Server-set element data uses `"deny"`. `elementdata_whitelisted=1`.
- Pure logic lives in `shared/logic/*.lua` and never calls MTA functions at file scope, so busted can `dofile` it with `tests/lua/helpers/mta_mock.lua`.
- No global tables used as static classes or singletons for a resource's state (`Maps = { stats = {}, … }`, `Character.byPlayer`): new code keeps state in file-local tables or closures, returns a module table, and passes state as arguments. The older `Character`/`Items`/`UI` globals are converted when their resource is reworked, not in passing.
- Never call `engineSetPoolCapacity("building", …)`: MTA grows the building pool on demand, and re-applying a capacity on a resource restart shrank a pool in use and crashed the client (2026-10-22).
- Style: `stylua` and `luacheck` clean before every commit. Conventional commits (`feat(items): …`).
- Git: commit straight to `main`; never create a branch unless asked. On prod the resources are a symlink into this
  clone, so switching branches there swaps the files the live server runs.
- Never commit `server-config/local.settings.xml` (holds the DB password).
- SA-MP-only object models (ids 11682–11753, 18631+) live in the `models` resource (`manifest.lua` + `files/`, both
  committed). When an item type starts using one that is not in the pack, run `python -m tools.extract_samp_models`
  on a box with a SA-MP client and commit the result. Clients create item objects with `ItemModels.forType(t)`;
  SA-MP models that clients build structures from (the pitched tent's panels and poles) are listed in
  `STRUCTURE_MODELS` in that tool and resolved with `ItemModels.forSamp(id)`.
- Skins whose mesh carries its own hat or helmet have a hatless twin in `models` (`peds.lua` + `files/<name>_nohat.dff`,
  built by `python -m tools.extract_ped_models` from `gta3.img` with Blender + DragonFF, see
  `docs/runbooks/add-hatless-skin.md`); `items` shows the twin on each client while a hat is worn, the server never
  changes the skin.
- Hat items cut off those skins (`SheriffHat`, `FireHelmet`, ...) are rows of `tools/port_hats.py`: port-only model ids
  20001+ in `models/hats.lua` + `files/<ped>_hat.dff`, built by `python -m tools.extract_ped_models --hats` (Blender,
  the remodel script's `--only hats`); the converters add the item type and its loot rows from the same table, and
  `apparel.lua` `CUT_HATS` wears them at zero offset on the head bone. Never list them in `extract_samp_models`.
- Forts are rebuilt from the fort kit, not from stock props: pieces are port models 20301–20399 (`models/fort.lua`, built by
  `python -m tools.make_fort_kit`, `--ariane DIR` packs them for the editor). A fort's layout lives in
  `maps/shared/forts.lua` (written by `python -m tools.fort_layout`, which samples the ground from a running Ariane), its
  upstream `.map` is listed in `REPLACED` in `tools/convert/maps.py` so `LS.lua` no longer places it, and
  `tools/fort_survey.py` measures an upstream fort against the Rockstar buildings before one is rebuilt.
- A twin's bare head is rebuilt from its reference image (`docs/images/hatless-refs`, `tools/hatless_refs.py`) by
  `python -m tools.hatless_rebuild prep|build <skin>` (cut plane per skin in `PLANES`, studio calibration in
  `tools/data`); the twin then brings a hair-only TXD of its own, listed as `txd` in `models/peds.lua`.

## Commands

- `pwsh tools/setup-dev.ps1` — hererocks Lua 5.1 + busted/luacheck/luacov, stylua, Python deps.
- `.lua/bin/busted.bat tests/lua` · `.lua/bin/luacheck.bat resources` · `stylua --check resources` · `pytest -q`
- `pwsh server-config/run-local.ps1` — create DB, apply `sql/schema.sql` and seeds, link resources into the MTA server, start it.
- `pwsh server-config/rcon.ps1 <command>` — drive the running server over its HTTP port (`help`, `players`, `rr items`,
  `cmd <player> additem M9Pistol`, `key <player> interact|inventory|arrow_d|enter|escape`, `lua return …`, `clua <player> <code>` (runs on that client, read the result with `chat`),
  `screenshot <player> [w h]`, `chat <player> [n|clear]` (last chat lines that client received; screenshots omit the chat box),
  `studio <player> [front|back|left|right|threequarter|top|face|hands|yaw dist height|off]`
  puts the ped alone on a chroma-green set for screenshots, see `docs/dev-studio.md`). MTA has no RCON; this is the `dev` resource's
  HTTP export. Verify MTA API names with the `mta-wiki` MCP (e.g. it is `takePlayerScreenShot`, capital S).
