# Plan: ScavengeSurvive → MTA:SA port repo (`scavengesurvive-mta`)

## Context

ScavengeSurvive (Southclaws) is a ~75k-line Pawn PvP survival gamemode for SA-MP 0.3.7, dormant upstream since 2021. The user (GitHub `VIRUXE`) already knows it well: they hold a fork, authored the open.mp port PR #653, and made a private FiveM port attempt in 2024. The goal now is a **planned, documented port to MTA:SA 1.6 (Lua)**, tracked in a new private GitHub repo that uses the GitHub feature set for planning (issues, milestones, Projects v2, templates, labels, Actions, releases, Dependabot, Discussions if available).

This plan produces three things:
1. A read-only reference clone of upstream ScavengeSurvive next to the new repo.
2. The `scavengesurvive-mta` repository: planning docs, port matrix, architecture, DB schema, roadmap, scaffolding (no gameplay code yet beyond skeletons).
3. The GitHub-side setup: repo, labels, milestones, epics/issues, project board, templates, workflows.

### Decisions already made by the user
| Decision | Value |
|---|---|
| Baseline | Upstream `Southclaws/ScavengeSurvive` `master` (v20.11 era) |
| Repo | `VIRUXE/scavengesurvive-mta`, **public**, **Unlicense** (new code) — public unlocks wiki, rulesets, CODEOWNERS, Pages, auto-merge, secret scanning |
| Naming | **No prefix.** The server exists only for this gamemode: resources are `core`, `items`, `auth`, … inside `resources/[scavengesurvive]/`; custom events use MTA's own `onXxx` convention (`onItemMoved`, `onCharacterSpawn`); no global Lua namespace table, each resource keeps its own locals/modules. Default MTA resources are **not installed** (avoids `admin`/`scoreboard` name collisions; documented in `server-config/`) |
| Database | **MariaDB-first**: use MariaDB 12.2 features wherever they remove Lua round-trips or in-memory state — stored procedures for item-graph moves, spatial indexes for proximity, event scheduler for loot/despawn, system-versioned tables for audit, `RETURNING`, generated columns, CHECK constraints, JSON functions, sequences (see Persistence) |
| Persistence | **MariaDB** via MTA `dbConnect("mysql")`; **write-through** (every mutation written immediately, read back from DB), only per-second tick stats (hunger/bleed/infection/drug fx) kept in memory and flushed every ~10 s and on state change |
| Scope | **Full plan up front covering every upstream subsystem**, in dependency order — but **not a 1:1 port**: keep the *essence* of the gamemode and make it better/more efficient on MTA. Features that are SA-MP-specific or impossible on MTA are classified drop/replace, not ported blindly |
| Resources | **No monolith**: one MTA resource per bounded domain (~17), DB is the only shared state |

### Design principle: essence over transcription (ADR 0008)
The port preserves **what Scavenge & Survive *is***, and is free to change **how it is built**:
- **Essence (non-negotiable)**: PvP-only survival on a decayed San Andreas ("San Androcalypse"); no commands, ~5 keys, everything is a physical item you see on the ground and interact with; the item graph (held / holstered / 6-slot inventory / bags / containers / trunks / safeboxes / tents); the wound-and-bleed damage model (no direct HP loss, wounds, knockouts, infection, hunger, drugs); the loot economy (weighted static spawns, supply drops, weapon caches); base building (defences, plot poles, keypads, workbench/machines, crafting); vehicles with fuel, locks and trunks; **permadeath**: one alive character, everything drops on death, combat-logging counts as death; the admin tiers and report culture; multi-language.
- **Free to reimagine**: implementation of every mechanism, UI (dx HUD/inventory instead of dialogs and textdraws), data model (MariaDB rows instead of modio blobs; persist *all* world items rather than only those within 20 m of a plot pole), sync model (client-side visuals, server-authoritative state), anticheat (MTA built-in + a few server sanity checks), the 9 known upstream bugs (fixed by default, each noted as an intentional deviation), balance constants (start from upstream values, tune later), tooling (no sampctl, no Go runner, no textdraw editor).
- **Where MTA makes it better for free**: native streaming (no streamer plugin), `createBuilding` for 23k static objects, client scripting for a real HUD/inventory/tooltips/3D labels, `bindKey`, colshapes, blips, `bcrypt` passwords, `attachTrailerToVehicle`, bone API for apparel, `getPlayerSerial` instead of GPCI, `fetchRemote`, `dbConnect` MariaDB, no 32k-item / 302-type / textdraw limits, per-player objects client-side.
- **Port-matrix classes are therefore**: `port` = same behaviour, new implementation (may simplify); `replace` = MTA-native mechanism supersedes it; `drop` = SA-MP-specific, no meaning on MTA; `defer` = content/nice-to-have after the core loop. "Parity" in milestone exit criteria means *the player experience matches*, verified by playtest checklists, not code equivalence.

## System design

### Requirements
**Functional**: the "essence" list above (survival stats, item graph, wound/bleed PvP, loot economy, base building, vehicles, permadeath, staff tooling, 10 languages), full subsystem coverage by M8.

**Non-functional (targets; recorded as `docs/04-architecture.md §NFR` and checked by the load test in `dev`)**
| NFR | Target | Rationale / how verified |
|---|---|---|
| Concurrent players | design for **200**, validate at **100** | SS servers historically ran 30–100; MTA comfortably exceeds; load test with 100 simulated clients in `dev` |
| Gameplay action latency (key press → server → UI update) | p95 < **150 ms** LAN, < **300 ms** internet | one procedure call + one `triggerClientEvent`; measured by `dev` queue-latency metric |
| DB write durability | no gameplay mutation lost on server crash; ≤ 10 s of tick stats lost | write-through + 10 s flush; `innodb_flush_log_at_trx_commit=1` in prod |
| Server tick budget | ≤ 30% of a 60 Hz frame at 100 players | `performancebrowser` per-resource CPU; no per-frame DB or export calls |
| Client FPS impact | ≤ 10% FPS loss from HUD/labels/apparel at 20 nearby players | render-target caching, capped label count, bone attach limits |
| Join time | world visible < 15 s on a mid PC | static world built client-side in batches; no server-element flood |
| Resource restart | any single resource restarts in < 5 s with no data loss | DB-only shared state; restart-resilience test |
| Availability | single server; planned restarts only; MariaDB backup nightly, PITR via binlog | runbooks |
| Cost | free tier everything (GitHub public, self-hosted server + MariaDB) | — |

**Constraints**: solo developer; MTA 1.6 stable client API (nightly-only features avoided or gated by `minclientversion`); MariaDB 12.2 with `mysql_native_password`; no legacy playerbase migration; upstream data licences (MPL-2.0 / CC BY-SA 4.0).

### Component diagram and data flow
```
┌────────────────────────────── MTA client (per player) ──────────────────────────────┐
│ ui (dx kit, cursor owner)   hud (bars, keys, hold, labels)   items/vehicles/…       │
│ (client halves: world projection per grid cell, inventory UI, damage cancel+report) │
└──────────────▲───────────────────────────────────────────────▲──────────────────────┘
   triggerClientEvent / latent (cell payloads, stats, UI models)   │ triggerServerEvent (on…Request…, validated: client, token, rate)
┌──────────────┴───────────────── MTA server (17 resources) ───┴──────────────────────┐
│ lib ─ data ─ ui ─ maps ─ auth ─ character ─ items ─ crafting ─ apparel ─ weapons      │
│ ─ vehicles ─ loot ─ building ─ world ─ hud ─ staff ─ dev                             │
│   • events on<Domain><Thing><Verb> (declared in every resource)                     │
│   • exports = coarse RPC by id (lib.rpc, nil when peer down)                        │
│   • in-memory: tick tables, id↔element maps, tokens, fire ring buffers              │
└──────────────┬──────────────────────────────────────────────────────────────────────┘
   dbConnect share=1 batch=0 queue=game (one FIFO worker)      queue=log (telemetry)
┌──────────────▼──────────────────────── MariaDB 12.2 ────────────────────────────────┐
│ tables (InnoDB, utf8mb4, system-versioned items/accounts/bans)                      │
│ stored procedures: item_pickup/drop, container_put/take/swap, character_death_drop,  │
│   craft_consume, ammo_split/merge  (transaction + EXIT HANDLER, single result row)   │
│ spatial indexes (items/loot_spawns/vehicles/constructions/trees)                     │
│ event scheduler: loot re-rolls, despawns, ban/mute expiry, log retention             │
└─────────────────────────────────────────────────────────────────────────────────────┘
```
**Primary flows**: (1) pickup: key → `onItemsRequestPickup` → validate → `CALL item_pickup` → result → update world projection for nearby players + inventory UI for owner. (2) survival tick: 1 s in-memory → `setElementHealth` → 10 s multi-row upsert. (3) damage: Appendix B. (4) loot: scheduler marks due spawns → `loot` polls due rows every 2 s → creates rows → `items` pushes cell deltas. (5) restart of any resource: `onResourceStop` flush → `onResourceStart` reload from DB → peers get `onResourceStart` and re-query.

### Load estimation (100 players, peak)
| Source | Rate | Notes |
|---|---|---|
| Gameplay mutations (pickup/drop/use/move/craft) | ~0.3 actions/s/player → **~30 procedure calls/s** | each ≤ 5 statements inside MariaDB |
| Cell/proximity queries for world projection | 1 per player per 2 s → **50 spatial queries/s** | indexed `MBRContains`; cached per cell for 2 s so co-located players share |
| Tick flush | 1 multi-row upsert / 10 s | 100 rows |
| Damage reports | bursty, ≤ 10/s/player rate-limited → **≤ 100/s** in-memory, DB only on wound/death | |
| Loot/despawn | scheduler-driven, ~5 rows/s | |
| **Total** | **~100–150 statements/s**, all indexed point/range ops | MariaDB on a small VPS sustains > 5k/s; the single FIFO queue is the real limit → alert if queue latency > 200 ms |
Bandwidth: cell payloads ~1–5 KB per cell change via latent events; stats sync ≤ 1 msg/s/player; no broadcast element data for per-player state.

### Failure modes and handling
| Failure | Effect | Handling |
|---|---|---|
| MariaDB down / unreachable | all mutations fail | `autoreconnect`; procedures return `false` → action refused with toast; `character` pauses tick flush and buffers dirty rows (bounded); staff alert; server continues read-only from memory |
| Queue backlog (slow query) | latency spike for everything | `dev` metric + alert > 200 ms; slow-query log; move offending reads to `queue=log` |
| Procedure error (constraint violation) | single action refused | `EXIT HANDLER` rollback; error code surfaced; system-versioned history for forensics |
| Resource crash/restart | its elements vanish | peers rebuild on `onResourceStart`; DB is truth |
| Client spoofing | rejected | `client` identity, tokens, rate limits, `elementdata_whitelisted`, `onPlayerChangesProtectedData`/`onPlayerTriggerEventThreshold` → log & kick |
| Server crash | ≤ 10 s tick stats lost, positions ≤ 10 s stale | write-through for everything else |
| Lost callback (player quit mid-query) | none | `isElement` check in every callback |

### Operations
- **Monitoring**: `dev` exposes `/metrics` (queue latency, procedure error counts, elements per resource, players, tick duration) and `performancebrowser` in dev; MariaDB slow query log + `db.log`; alerts via Discord webhook (`fetchRemote`) in M7.
- **Backup/recovery**: nightly `mariadb-dump --single-transaction` + binlog for PITR; system-versioned tables give item/account history without restores; restore runbook tested in M7.
- **Deploy**: tagged release zip → server `resources/`; migrations applied by `run-local.ps1`/`deploy.ps1` before start; `refreshResources` not used in prod (full restart at low population).

### What to revisit as it grows
- >150 players: second FIFO queue split by domain (items vs character) once ordering dependencies are documented; read replicas are unnecessary at this scale.
- >5k live world items near hubs: per-cell payload compression, item pooling client-side, `createBuilding` for immovable placed structures.
- Multiple game servers: not in scope; would require region sharding of the item graph.

## Target architecture (summary; full detail goes into `docs/04-architecture.md`)

### Resource decomposition (user: **no monolith, no prefix**) — one resource per bounded domain, DB is the only shared state
All under `resources/[scavengesurvive]/`. Cross-resource contract: **pass ids (item id, character id, container id), never element handles or cached tables**; notifications via `triggerEvent` with MTA-style names (`onItemMoved`, `onCharacterDeath`), queries via exports (kept out of per-frame paths). Every resource re-syncs from DB on its own `onResourceStart` and listens for `onResourceStart` of its dependencies, so any resource can be restarted alone. (Exact lifecycle/export/event semantics are being verified by the MTA documentation research and will be recorded in `docs/04-architecture.md`.)

**Lifecycle rules (verified in `CResource.cpp`/`CResourceManager.cpp`)**: `<include>` only auto-starts dependencies and fails the start if one is missing — it never stops or restarts dependents, and `minversion`/`maxversion` are ignored ⇒ **all resources are started from `mtaserver.conf` `startup="1"` in dependency order** (`lib, data, ui, maps, auth, character, items, crafting, apparel, weapons, vehicles, loot, building, world, hud, staff`), `<include>` used only as a "must exist" declaration. Only `core`-equivalent `character` is `type="gamemode"`; mapmanager/mapcycler/votemanager/play/spawnmanager/scoreboard and the rest of the stock start list are removed; `setGameType`/`setMapName` called by `character`. Elements are destroyed with their creating resource's element group even if reparented; timers, handlers, key binds and `addEvent` registrations die with the VM ⇒ every resource rebuilds from MariaDB in `onResourceStart` and persists in `onResourceStop` (VM and elements still valid there). Exports into a stopped resource return `nil`/`false` with a log line, never throw ⇒ `lib.rpc(res, fn, ...)` checks `getResourceState == "running"`. Export arguments are deep-copied (metatables lost, functions → nil). `download_priority_group`: `lib` 100, `data` 95, `ui` 90, `hud` 80. Trade-off accepted: more `meta.xml`/export bookkeeping and marshalled cross-resource calls; hot path (pickup→inventory→container) stays inside `items` and, below it, inside MariaDB stored procedures.

### Persistence (MariaDB 12.2, write-through, MariaDB-first)
**Use the database engine for game logic that would otherwise be Lua round-trips or cached state** (each item below is a verification task in the MTA DB research — MTA talks MySQL client protocol; must confirm `CALL` with result sets, `RETURNING`, spatial types and MariaDB auth plugins work through `dbQuery`):
- **Stored procedures for the item graph** (`sql/procedures/*.sql`): `item_pickup(item, char)`, `item_drop(item, char, x,y,z,rz, interior, dimension)`, `item_holster/unholster`, `container_put(item, container)` (capacity check with `SELECT … FOR UPDATE` + dense-slot assignment), `container_take`, `container_swap`, `character_death_drop(char, x,y,z)`, `craft_consume(char, recipe_json)`, `ammo_split/merge`. One round trip, atomic, and the invariants are enforced no matter which resource calls them ⇒ this is what makes "many resources, DB as the only shared state" safe. Each returns a single result row `(ok, code, payload_json)`.
- **Spatial**: `POINT` columns with `SPATIAL INDEX` on `items`, `loot_spawns`, `vehicles`, `constructions`, `trees` ⇒ "everything within R of player" is one indexed `ST_Within(pos, ST_Buffer(...))`/`MBRContains` query; replaces the 200 m cell hack and MapAndreas.
- **Event scheduler** (`SET GLOBAL event_scheduler=ON`): loot re-roll due times, item despawn (`despawn_at`), timed bans/mutes expiry, vehicle cleanup, connection-log retention — server just materialises what the DB rolled.
- **System-versioned tables** (`WITH SYSTEM VERSIONING`) on `items`, `accounts`, `bans`, `admin_actions` ⇒ full audit history for "where did this item come from" and admin abuse checks, without Lua logging.
- **`INSERT … RETURNING` / `DELETE … RETURNING`** to get ids/rows back in one statement; `INSERT … ON DUPLICATE KEY UPDATE` for the tick flush; **generated columns** (`alive_account` uniqueness, cell/zone tags) and **CHECK constraints** (exactly-one-location); **JSON** columns + `JSON_VALUE`/`JSON_TABLE` for item data, wounds, drugs; **sequences** for readable item serials; **invisible columns** for audit metadata; **application-time periods** for bans/mutes; **triggers** to maintain `containers.used_units`; **`INSERT … SELECT` bulk seeding**; InnoDB with `innodb_flush_log_at_trx_commit=2` recommended for dev.
- **Migrations** stay plain SQL files applied by `lib/migrate.lua` (one statement per `dbExec`, no `DELIMITER`; procedure bodies sent whole) and by the `mariadb` CLI / CI against a MariaDB service (`DELIMITER` allowed there) — generated from one source by `tools/sql_split.py`.

**Verified driver facts (mtasa-blue `Server/dbconmy/CDatabaseConnectionMySql.cpp`, `CDatabaseTypeMySql.cpp`, `CDatabaseJobQueue.cpp`, `CLuaDatabaseDefs.cpp`)** — these fix the connection design:
- MTA links Oracle `libmysqlclient` 8.4 (Windows: mysql-8.4.6 + OpenSSL 3.4.2; Linux: Ubuntu 24.04 `libmysqlclient21`). MariaDB user must use **`mysql_native_password`** (MariaDB's `CREATE USER … IDENTIFIED BY` default); `ed25519`/PARSEC will fail; `caching_sha2_password` (MariaDB 12.1+) probably works (`get_server_public_key=1`). TLS via `use_ssl=1` = encrypt-only, no CA verification.
- **`CALL proc()` returning result sets works**: the driver drains all results with `mysql_next_result` (CLIENT_MULTI_RESULTS is libmysqlclient default). `dbPoll(qh, t, true)` returns every result set; without it, the first. `INSERT … RETURNING` works as an ordinary result set.
- **`batch=1` (default) is dangerous here**: it wraps every frame's queued statements in an implicit `autocommit=0` transaction committed by a per-frame FLUSH; one InnoDB error/deadlock discards the whole batch for every resource on a shared connection, and an explicit `START TRANSACTION` split across calls gets committed early ⇒ **use `batch=0`**; atomicity lives **inside stored procedures** with `DECLARE EXIT HANDLER FOR SQLEXCEPTION BEGIN ROLLBACK; RESIGNAL; END`. A failed multi-statement string sends **no ROLLBACK** (transaction stays open on the shared connection) ⇒ never hand-roll multi-statement transactions.
- Placeholders are **client-side string substitution** (no server prepares): `?` → escaped quoted string / `%lld` / `%f` (**6 decimals**) / `1|0` / `NULL`; `??` = escaped, unquoted; **every `?` in the SQL text is a placeholder, even inside literals or procedure bodies** (use `CHAR(63)`); escaping breaks under `sql_mode NO_BACKSLASH_ESCAPES`. `dbPrepareString` fragments are safe to concatenate.
- Type mapping to Lua: INT/BIGINT → number (exact ≤2^53); **FLOAT/DOUBLE → 32-bit float** (≈7 significant digits; fine for GTA coordinates ±3000 at ~0.0002 precision, not for anything else) ⇒ store money/counters as integers, `CAST(x AS DECIMAL(12,4))` when precision matters; **DECIMAL/SUM/AVG → string** (`tonumber`); **NULL → `false`**; JSON/TEXT/BLOB → binary-safe string (`fromJSON`); DATETIME/ENUM → string; BIT → raw bytes (`col+0`); **GEOMETRY → raw SRID+WKB bytes** ⇒ always `SELECT ST_X(pos), ST_Y(pos)` or `ST_AsText(pos)`.
- One worker thread per **queue name** (default queue = host string), strict FIFO across all resources on that queue; `share=1` (default is **0**) shares the connection across resources only when host+user+full option string match; shared connection = shared session state (avoid `@vars`/temp tables). `dbConnect` blocks (call once at resource start); `dbExec` swallows errors (debug warning only) ⇒ wrap with `dbQuery`+callback; `dbPoll` returns `nil` (pending) / `false, code, msg` / `rows, affected, insertId`. `suppress=1062` honoured for mysql. Warnings above 20 connections or 200 jobs/10 s (soft). `database_credentials_protection=1` blocks `fileOpen` on script files of DB-using resources.

**Connection (every resource, identical string so `share=1` matches):**
```lua
dbConnect("mysql", "dbname=scavengesurvive;host=127.0.0.1;port=3306;charset=utf8mb4", user, pass,
          "share=1;batch=0;autoreconnect=1;multi_statements=0;queue=game;log=1;tag=game;suppress=1062")
-- second connection for logs/telemetry/admin history: "...;batch=1;queue=log;tag=log"
```
- Narrow API in `db.lua`: `query(sql, params, cb, ctx)`, `one`, `exec` (via `dbQuery` so errors are logged), `call(proc, params, cb, ctx)` (returns first result row `(ok, code, payload_json)`), `prep`. No `tx` helper. Callbacks always fire (`false` on error), check `isElement(player)` before touching a player, `ctx` carries the action token so stale callbacks are dropped.
- Server config: `event_scheduler=ON`, `sql_mode` without `NO_BACKSLASH_ESCAPES`, `innodb_flush_log_at_trx_commit=2` for dev; DB user `app` with EXECUTE/SELECT/INSERT/UPDATE/DELETE, separate DDL user for migrations. After connect verify `SELECT @@character_set_connection, @@collation_connection` (MySQL 8 client announces `utf8mb4_0900_ai_ci`, aliased to `uca1400` on MariaDB ≥ 11.4.5). Day-1 spike in `dev`: `share=1` cross-resource, `CALL` round trip, `caching_sha2_password`.
- MTA's own accounts (`internal.db` SQLite, `setAccountData` scalars) are used **only for staff ACL** (`aclGroupAddObject("user.NAME")` gating engine rights); game accounts live in MariaDB with `passwordHash(pw, "bcrypt", {cost=10}, cb)` (r22701+, async form).
- **Atomic moves = stored procedures** (`item_pickup`, `item_drop`, `container_put`, `container_take`, `container_swap`, `character_death_drop`, `craft_consume`, `ammo_split/merge`), each a transaction with `SELECT … FOR UPDATE` guards, EXIT-HANDLER rollback, and a single `SELECT ok, code, payload` result. Simple single-row moves are still compare-and-set `UPDATE … WHERE <still where we think it is>` (affectedRows 0 ⇒ refused). `UNIQUE(holder_char_id, holder_kind)` (kinds: `held`, `holster`, `bag`, `hat`, `mask`, `armour`), `UNIQUE(container_id, slot)`, `UNIQUE(loot_spawn_id)` and a CHECK that exactly one location is set make double-occupancy impossible even if a caller is wrong. Containers in SS are a **size-unit budget with dense ordered slots** (sum of item-type sizes ≤ container size; slots shift on removal) — `containers.used_units` maintained by trigger, capacity checked inside `container_put`.
- **In memory only**: item id↔element maps (client-side world projection per grid cell), per-player tick table (hp/hunger/thirst/bleed/infection/drugs, `dirty`), identity maps, tokens/rate limiters, per-shooter fire ring buffer. Inventory/container contents are `SELECT`ed on open.
- **Tick flush**: 1 s server tick updates memory + `setElementHealth`; every 10 s one multi-row `INSERT … ON DUPLICATE KEY UPDATE` for dirty characters (stats + position); immediate flush on consume/heal/damage/death/vehicle enter-exit/teleport/logout and synchronous on `onResourceStop`.
- **Schema (migrations in `sql/migrations/0001_init.sql`)**: `schema_migrations`, `accounts`, `characters` (stats, position, `inventory_container_id`, one-alive-per-account via generated column UNIQUE), `containers` (kind enum, size, owner item/vehicle/char, keypad, locked), `items` (type_uname, hitpoints, `data JSON`, exactly-one-location columns, `pos POINT` + SPATIAL INDEX, despawn_at, system-versioned), `vehicles`, `vehicle_spawns`, `constructions`, `plots`, `trees` (planted only), `loot_spawns` + `loot_spawn_state`, `bans`, `whitelist`, `reports`, `staff_actions`, `connection_log`, `settings`. InnoDB, utf8mb4. Item **types stay Lua data** in `data` (versioned, shared client/server); a tiny `item_type_registry` is written at start for staff joins.
- Passwords: bcrypt, **no Whirlpool import** (MTA cannot verify it); optional legacy name/admin-level import with forced password set.

### Architecture decisions — options considered (each becomes a full ADR in `docs/adr/`, status Accepted unless marked Proposed)
| ADR | Decision | Options considered (rejected → why) | Consequences / revisit |
|---|---|---|---|
| 0001 MariaDB write-through | every mutation hits MariaDB immediately; only tick stats batched | (a) in-memory state + periodic save like upstream → data loss on crash, restart coupling; (b) Redis/cache layer → extra service, user asked for minimal caching; (c) SQLite via `dbConnect("sqlite")` → no procedures/spatial/versioning, single-writer | single FIFO queue is the throughput ceiling; revisit at >150 players |
| 0002 Many resources, not monolith | 17 domain resources, DB as only shared state | (a) one `core` resource with modules → fastest calls, but restart = whole game, user rejected; (b) core + satellites (agent's proposal) → still a gameplay monolith; (c) one resource per Pawn file (~240) → meta.xml/export explosion | more `addEvent`/export bookkeeping; `check_meta.py` enforces contracts |
| 0003 dx UI over CEGUI/CEF | dx immediate-mode + RT caching for player UI; CEGUI/CEF only for text-heavy forms | CEGUI everywhere → fixed look, poor fit for HUD; CEF everywhere → memory + Lua↔JS latency on drag, unstated cost | icon atlas pipeline is an offline step; revisit CEF for staff panel |
| 0004 No legacy password import | bcrypt only; optional name/admin-level import with forced reset | implement Whirlpool in Lua → slow, no `hash()` support, no live playerbase to justify | first login of imported names = set password flow |
| 0005 License split | Unlicense (code) + MPL-2.0 (ported data) + CC BY-SA 4.0 (maps) | single Unlicense → violates upstream terms for verbatim data; MPL for everything → unnecessary copyleft on new code | `THIRD_PARTY_NOTICES.md`; converters emit licence headers |
| 0006 Drop SA-MP anticheat | MTA built-in AC + server sanity checks (teleport, locked vehicle, ammo, ping, flood, alt-tab, traps, detection fields) | port all 15 checks → most are SA-MP sync artefacts | keep a list in port matrix with `port/drop` reasons |
| 0007 Fix known upstream bugs | fix all 9, document as intentional deviations | preserve for fidelity → nobody wants healer-infecting bandages | playtest checklist notes deviations |
| 0008 Essence over transcription | behaviour parity by playtest, implementation free | 1:1 file-by-file port → carries SA-MP workarounds, user rejected | port matrix has `port/replace/drop/defer` classes |
| 0009 Persist all world items | every world item is a DB row (spatial-indexed), not only near plot poles | upstream 20 m plot-pole rule → arbitrary loss, was a file-count workaround | despawn policy via scheduler (`despawn_at`) replaces the rule |
| 0010 Stored procedures for the item graph | atomic moves in MariaDB procedures | Lua multi-statement transactions → no rollback on error + `batch` hazards (verified in driver); optimistic CAS only → can't check container capacity atomically | procedure tests in CI; SQL split for CLI vs MTA |
| 0011 Client-built static world & world projection | buildings/objects created client-side from data and cell payloads | server elements for maps/items → 131k element cap, join flood, streamer caps | client memory/pool tuning; `enginePreloadWorldArea` on teleport |
| 0012 Command binds for gameplay keys (Proposed) | `bindKey(key,"down","cmd")` so players rebind in MTA settings | function binds → not user-rebindable | commands must be non-restricted and cheap |

### Client/server split and anti-spoof
Damage: client cancels `onClientPlayerDamage`, reports to server, server validates (weapon/distance/rate/fire ring buffer) and computes the wound → `setElementHealth`/`killPed` (see Appendix B). HUD/dialogs: dx via `ui`, stats pushed by `triggerClientEvent` on change (or `"subscribe"` element data for owner + spectating staff). Keys: command binds (`bindKey(key, "down", "cmd")`) so players rebind in MTA settings. Hold actions: server timer decides completion. 3D labels/tooltips: client-created objects per grid cell + static item table shipped in `data`; `elementdata_whitelisted=1`, any server-set key uses `"deny"`. All remote handlers go through one `lib.net.handler` wrapper: `client` is the only trusted identity, `isElement` re-validation, one-shot server tokens for mutating UI actions, per-event rate limits, `sourceResource` allow-list / `restricted="true"` on sensitive exports. Client never sets element data (CI grep rejects `setElementData(` in `client/`).

## Appendix B — How MTA actually works (documentation + engine-source digest; drives `docs/02-samp-vs-mta.md` and `docs/04-architecture.md`)

**Sync, damage, weapons, anticheat** (wiki + `mtasa-blue` master; re-check against the installed 1.6 build)
- **The victim's own client owns its health/armour/weapon/ammo**; the server stores what the pure-sync packet reports (clamped) every `player_sync_interval` (100 ms; lightweight sync 1500 ms at distance). `onPlayerDamage` (server) is just the health drop between two packets — not cancellable, no killing hit. Remote players' health is locked to the synced value on every client.
- **No snap-back**: `setElementHealth`, `setPedArmor`, `setElementPosition`, weapon-slot and animation setters stamp a new *sync time context*; packets with the old context are dropped ⇒ server-authoritative HP is safe. `setElementVelocity` and `setWeaponAmmo` do **not** stamp a context (≈1 RTT window where stale client ammo can reappear).
- **Do NOT set weapon damage to 0**: `onClientPlayerDamage` only fires when GTA actually changed health/armour ⇒ keep damage > 0 (all three skill tiers), and on the victim's client `cancelEvent()` then report the hit. `setWeaponProperty` has no `flag_disable_model`.
- **Server has no line-of-sight** (`processLineOfSight`/`isLineOfSightClear`/`getPedBonePosition`/`getElementDistanceFromCentreOfMassToBaseOfModel` are client-only). `onPlayerWeaponFire` fires only for bullet-sync weapons (22–34) and, on master, is pre-gated by the engine (must hold weapon with ammo, shot length ≤ range×1.1+15, ≥40 ms between shots); `hitElement` unreliable. Damage type ids: 19 rocket, 37 burnt, 49 rammed, 50 run-over, 51 explosion, 53 drowned, 54 fall, 63 blown; melee = weapon 0; head = bodypart 9.
- **Kill credit**: `setElementHealth(p,0)` fires wasted with killer=false ⇒ use `killPed(victim, killer, weapon, bodypart)`.
- **Ammo design**: authoritative magazine+reserve in server table; mirror only the magazine into GTA via `setWeaponAmmo(p, w, mag, mag)` so GTA cannot auto-reload; decrement on `onPlayerWeaponFire` (client report for non-bullet-sync weapons, rate-limited); reload is a server request; `toggleControl(p,"fire",false)` while empty/reloading. `reloadPedWeapon` is server-only and may silently fail; `isPedReloadingWeapon` is synced.
- **Built-in AC** blocks trainers/dll/speed/health-hack *tools*, not gameplay values ⇒ scripts must validate distance/rate/possession. `enablesd` defaults `31,32`; consider 12, 20, 33 for PvP. `onPlayerTriggerEventThreshold` + `max_player_triggered_events_per_interval` (100/1000 ms) are the built-in event-spam guard. `resendPlayerACInfo` in `onResourceStart`. Ban via `banPlayer(p, ip, username, serial, responsible, reason, seconds)` / `addBan` (needs ACL rights). Serial "could be non-unique or faked" ⇒ pair with accounts.
- **Controls/anims**: `toggleControl`/`toggleAllControls` both sides (block `fire` **and** `action`); `setElementFrozen` cancels `setPedAnimation`; `setPedAnimation(..., interruptable=false)` for knockout; drunk effect = `setCameraDrunkLevel(0–255)` (client, r21795) + `setPlayerBlurLevel`; no `setPedDrunk`; `setPedChoking` server-only cough; `setPedWalkingStyle` for limp; `setPedHeadless` for headshot visual; `setPedStat` 22 stamina / 24 max health / 69–79 weapon skills.
- **Vehicles**: `setVehicleLocked` doesn't stop open-door/doorless entry ⇒ cancel `onVehicleStartEnter`; engine auto-starts on driver entry unless scripted; `setVehicleDoorsUndamageable` only while locked; `setVehicleDamageProof` also stops bike knock-offs (prefer cancelling damage events); door 1 = trunk (`setVehicleDoorOpenRatio`); `setVehiclePanelState` syncs only from server; **no native fuel**; `onTrailerAttach` cancel unreliable (detach with 50 ms timer); `engineRequestModel` client-only and not reverted on stop (`engineFreeModel`; "newmodels" resource pattern for synced ids).
**Resources, events, elements, element data** (wiki + `mtasa-blue` source)
- **Custom events are global per side but reference-counted per resource**: `addEvent(name, flag)` in **every** resource that triggers or handles it (same `allowRemoteTrigger` everywhere — a mismatching `addEvent` returns false and does not register); `addEventHandler` fails if the event doesn't exist yet; `triggerEvent` returns `nil` (no such event) / `false` (cancelled) / `true`. Naming: `on<Domain><Thing><Verb>` (`onItemMoved`, `onCharacterSpawned`), server→client `onClient<Domain>…`, client→server `on<Domain>Request…` — the only remote-triggerable ones, every handler checks `client`. Trigger on the narrowest element (player, item, `resourceRoot`), never `root` (walks the whole tree); attach handlers to the producer's `resourceRoot`. Cancelling sets a flag but does not stop remaining handlers; use `triggerEvent` return + `getCancelReason()` for veto hooks. `triggerClientEvent` accepts a table of players; `triggerLatentClientEvent(bandwidth bytes/s, persist=false)` for big payloads, not ordered with normal events. Built-in spam guard: `max_player_triggered_events_per_interval` 100/1000 ms → `onPlayerTriggerEventThreshold`, plus `onPlayerTriggerInvalidEvent`.
- **Element data**: `setElementData(el, key, value, "broadcast"|"local"|"subscribe", "default"|"allow"|"deny")`; with `elementdata_whitelisted=0` (default) **any client can set any key on any element** ⇒ set `1`, handle `onPlayerChangesProtectedData` centrally. Unchanged values are free; each broadcast = one RPC × players ⇒ default `"local"`, `"broadcast"` for nametag/faction-style values, `"subscribe"` + `addElementDataSubscriber` for per-owner stats (owner + spectating staff). Per-item labels/tooltips: neither element data nor custom elements — static item table shipped in `data` as client script + per-instance state via `triggerClientEvent`. Keys namespaced `char.hunger`, `veh.fuel`; one owning resource per key. Cancelling `onElementDataChange` is marked 1.7 on the wiki.
- **`createElement` dummies are sent to every client and cost an id** (131072 cap; "element id starvation" can fail a resource start) and have no position for `getElementsWithinRange` ⇒ use only for a few thousand world-visible entities that need a handle; inventory rows stay Lua tables/DB. `setElementVisibleTo` only markers/blips/radar areas. Colshape tests ignore dimension/interior ⇒ check manually. `setElementSyncer(true)` for parked vehicles + `setElementFrozen` until entered.
- **Commands**: `addCommandHandler(cmd, fn, restricted, caseSensitive=false for player commands)`; `restricted=true` ⇒ ACL `command.<cmd>`; `allow_multi_command_handlers=0` to catch duplicates across resources; `onPlayerCommand` fires for chat `say` too (keep cheap); `onPlayerChat` cancel suppresses delivery **and** server log (log via `outputServerLog`); `outputChatBox(text, playersTable, r,g,b, true)` hex codes uppercase; `setPlayerName` 1–22 chars no spaces ⇒ character display names via UI.
- Timers: min interval 0 ms, `times=0` forever, arguments copied like exports, `source` nil inside, destroyed with VM ⇒ one scheduler timer per resource iterating players. `getRealTime().timestamp` for DB times, `getTickCount()` for cooldowns.
- Server config: `elementdata_whitelisted=1`, `minclientversion` + `minclientversion_auto_update=1`, `fpslimit` 60–74, `bandwidth_reduction` medium/maximum, `database_credentials_protection=1` (blocks `fileOpen` on scripts of DB-using resources ⇒ DB credentials in meta.xml `<settings>` read via `get()`), `backup_*` covers server files only (MariaDB backed up separately), `resource_client_file_checks=1`, `scriptdebugloglevel` 3 dev / 2 prod, keep `performancebrowser` in dev for leak hunting. `startResource` from scripts adds a temporary include (dies with caller) unless `persistent=true`.

**World, objects, streaming, areas** (wiki + `mtasa-blue` source)
- **Server `createObject` rejects model ids ≥ 20001 and non-vanilla ids; MTA has none of SA-MP's added objects** (SA-MP-only ids fail with "Bad 'model' id") ⇒ `tools/convert/maps.py` must classify every model id as vanilla / SA-MP-only, report counts, and SA-MP-only models (incl. hollow-house models 19490/19492/19494/19496 used by house loot) become an explicit decision: replace with vanilla equivalents, drop, or ship custom DFF/COL via `engineLoadDFF`+`engineRequestModel` (client-only ids, `newmodels` pattern; licensing of SA-MP assets must be checked first).
- **Every server element replicates to every client** and counts toward `MAX_SERVER/CLIENT_ELEMENTS 131072`; client object streamer caps at 1000 (500 normal + 500 low-LOD), vehicles 64, peds 110, markers 32, pickups 620 ⇒ **static world is built client-side** from shared data files (`createBuilding`, batched ~100/frame in a coroutine; `engineSetPoolCapacity("building", n)`, default 13000, auto-grows), objects only for scaled/dimensioned/non-building-valid models; **world items are client-created per grid cell** from server-sent cell payloads (`triggerLatentClientEvent`), authoritative state in MariaDB; **loot spawns are not colshapes** (DB spatial query / grid polling every 1–2 s). `getElementsWithinRange` is a box and ignores custom `createElement` types.
- `createBuilding` (r22410; **server-side since PR #3897, 2025-05**): x/y within ±3000, vanilla models only (rejects 384–397), no `setObjectScale`; dimension/interior on buildings only in nightlies after 2026-08/09 (#5139, #5444) ⇒ pin `minclientversion` or treat buildings as all-dimension. LOD via `setLowLODElement`; `engineSetModelLODDistance` ≤170 recommended, 325 cap (extendedLod beyond). `enginePreloadWorldArea` for teleports.
- `removeWorldModel(model, radius, x,y,z[, interior])` (note arg order differs from SA-MP) **plus its LOD model** (editor's `LOD_MAP` table in `[editor]/editor_main/server/saveloadtest_server.lua`; or `processLineOfSight(..., includeWorldModelInformation)` → `worldLODModelID`), then `setOcclusionsEnabled(false)`. `.map` `<removeWorldObject>` is only honoured by the editor's injected script, not the engine.
- **Rotation convention**: MTA objects rotate ZXY, vehicles ZYX; SA-MP→MTA converters copy rx/ry/rz verbatim, but no official equivalence statement ⇒ M0 spike: place one asymmetric 3-axis-rotated object both ways and compare.
- Stream-in distances: objects 500, low-LOD 1700, markers 600, players/vehicles 250, pickups 100; streamer processes 6 in/6 out per step. `setElementStreamable(false)` only for a handful of elements.
- Dimensions 0–65535 (`-1` = all, objects only) = SA-MP virtual world; interior = interior.
- Server has **no collision data**: ground Z for 11k loot spawns is precomputed offline (`SAmin.hmap` reader in `pyss/`) or by a trusted client one-off in `dev`. Client-only: `getGroundPosition`, `processLineOfSight`, `testLineAgainstWater`, `getWaterLevel`.
- Ladders: no GTA ladder anims — use `dam_jump/climb_*` or `finale/fin_hang_loop` + scripted movement; ziplines: server `moveObject` invisible carrier + `attachElements` player + hang anim. Supply drops: server object + `moveObject` descent, attached parachute model, client smoke, `createBlipAttachedTo`, small colshape.
- `setMinuteDuration` default 1000 ms (60000 = real time); `setWorldSpecialPropertyEnabled("randomfoliage", false)` to strip grass; `vehicle_engine_autostart` property (1.6) to stop engines auto-starting.

**Client rendering, UI, input** (wiki; versions: set `<min_mta_version client>` from the highest revision used and test on a real client)
- Frame order: world update → `onClientPreRender(timeSlice)` (world-attached dx, 3D labels) → `onClientPedsProcessed` (bone attachments, r22649) → `onClientHUDRender` (full-screen effects behind HUD, r22649) → GTA HUD → `onClientRender` (2D UI). One render handler dispatching to active modules.
- **Render-target caching** exactly as `[gameplay]/scoreboard/dxscoreboard_rt.lua`: redraw only when dirty or every ~1 s, `modulate_add` when writing text to RT and `add` when blitting, recreate on size change, fall back to direct draw if `dxCreateRenderTarget` fails, redraw on `onClientRestore(didClearRenderTargets)`. `postGUI=true` draws never land on a render target.
- Scaling: single factor `s = screenH/1080`, edge/centre anchors, rebuild fonts/RTs when `s` changes; `dxSetAspectRatioAdjustmentEnabled` is for 4:3-authored HUD alignment, not new UI. `dxGetTextSize` (r22271) for tooltip sizing; `colorCoded=true` disables `clip`/`wordBreak`; create `dxCreateFont` after `onClientResourceStart`; textures via `dxCreateTexture(path,"dxt5",true,"clamp")` never `dxDrawImage(path)`; `dxDrawImageSection` for atlases; `svgCreate` for vector panels/icons; `dxDrawCircle` for radial hold progress.
- **Item icons must be pre-rendered offline** (`dxDrawModel3D` r22708 cannot draw to a render target; `object_preview` resource + `saveRTToFile`, or Blender) → 128² PNG → DXT5 atlases → `itemUname → {atlas,u,v}`; placeholder glyph when missing. `engineGetModelTextures` gives raw materials only.
- 3D labels: cache streamed-in item objects via `onClientElementStreamIn/Out`, distance-cull, `getScreenFromWorldPosition` (no visibility check), `isLineOfSightClear` at ≤5–10 Hz per label, draw within ~20–30 m.
- Input: **gameplay actions are command binds** (`addCommandHandler("inv_toggle")` + `bindKey("h","down","inv_toggle")`) so players rebind in MTA Settings; show keys with `getKeyBoundToCommand`. Guard handlers with `isChatBoxInputActive()`/`isConsoleActive()`/`isMainMenuActive()`/dx-field focus. `onClientKey` cancel swallows GTA+MTA binds for that key (escape once, F8 never). `onClientMouseWheel` is GUI-only → use `onClientKey("mouse_wheel_*")`. `onClientClick`/`getCursorPosition` only while cursor shown (relative coords); no native dx hit-test → own rect tests in panel-local coords. `showCursor(true)` disables controls by default (don't also `toggleAllControls` so chat stays); a cursor shown by one resource can't be hidden by another ⇒ **`ui` resource owns the cursor**. `toggleControl` must disable both `fire` and `action` to block firing. Text entry: `onClientCharacter` for dx fields; `guiSetInputMode("no_binds_when_editing")` for CEGUI/CEF. Prefs in `@`-prefixed private XML (`xmlCreateFile("@prefs.xml")`).
- UI tech: **dx immediate-mode + small retained widget list + RT cache** for inventory/containers/HUD/keypad/radio/watch/death screen; **CEGUI or CEF** only for text-heavy forms (login/register with `guiEditSetMasked`, admin panel grid lists as MTA's `admin` does); CEF (`createBrowser` + `http://mta/local/`, every file in meta `<file>`) has unstated memory cost and Lua↔JS latency ⇒ not for inventory or HUD.
- HUD/camera: `setPlayerHudComponentVisible("all", false)`; `setPlayerHudComponentProperty` (r22868); low-HP/knockout = red vignette in `onClientHUDRender` + `setBlurLevel` + `setCameraDrunkLevel` + `fadeCamera`; death screen = `setCameraMatrix` at corpse + `toggleAllControls(false, true, false)` + dx overlay; nametags via `setPlayerNametagShowing/Text/Color`.
- Audio: radio item = `playSound3D(url|file)` attached to carrier (`attachElements` accepts sounds; keep one rotation offset 0) + `setSoundMaxDistance`; `setSoundEffectEnabled(player, "distortion")` for walkie-talkie voice; `playSFX3D` for GTA SFX; voice needs `voice=1` + voice resource, `setPlayerVoiceBroadcastTo` for proximity.
- Custom models: load COL → TXD → DFF; `engineRequestModel` ids are client-local and differ per client ⇒ sync string keys, map per client; `engineFreeModel` on stop (freed elements fall back to model 1337); `engineLoadTXD(path, false)` for pre-mipmapped TXDs.

- **Damage architecture (final)**: victim client `onClientPlayerDamage(localPlayer)` → `cancelEvent()` → `triggerServerEvent("onPlayerHitReport", attacker, weapon, bodypart)` (no damage value) → server matches against a per-shooter ring buffer of `onPlayerWeaponFire` records (ping+150 ms), checks possession/ammo/range/rate/dimension/alive → computes wound (calibre, muzzle velocity, server distance, body-part ×, armour/shield from server state) → `setElementHealth` / `killPed` → `triggerClientEvent` wound state to HUD → enforce in `onPlayerDamage`: if reported HP > server HP, restore + flag. Must trust client for: hit registration, body part, aim vectors, own position/anim, fall/drown/fire events, anything LOS/bone.
