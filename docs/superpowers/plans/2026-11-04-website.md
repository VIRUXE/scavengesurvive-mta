# Website plan: scavengesurvive-mta on GitHub Pages

Status: approved 2026-11-04 (wiki source moved into `wiki/` with a mirror job, Pages from `site/` on `main`, English and Portuguese); built the same day.

## 1. What the upstream site is (reference)

`scavengesurvive.com` (Docusaurus, 2023, by Southclaws):

- Hero: hammer logo + wordmark, one paragraph ("a PvP survival game where everyone is pitched against each other…"), "Scroll down for a quick overview…".
- Five feature slates with a rusted-metal header bar: **Objective, Survival, Building, Combat, Crafting**, each a blurred screenshot with four one-line promises.
- A "Videos" section with three YouTube embeds.
- Top nav: Docs (the game wiki), Servers (a static server list merged with open.mp's), English / Português, GitHub.
- Dark theme by default.

Our site keeps that skeleton (hero, feature slates, media, docs link, servers, two languages ready) and adds what upstream never had to sell: the port itself, what changed, and why MTA.

## 2. Goals

1. Sell the game to a player who has never heard of it (one screen to "Join").
2. Sell the port to an upstream player: every difference, honestly, with the numbers.
3. Sell MTA:SA to SA-MP / open.mp players: what the platform makes possible, with our features as the proof.
4. Be the front door to the wiki, the source and the Discord.
5. Look spectacular: this is the one thing a visitor judges in two seconds.

## 3. Where it lives and how it ships

- Source in `site/` on `main`: plain HTML, CSS and JavaScript, no framework, no build step, no npm. One shared stylesheet and script, one `assets/` tree.
- Deployed by a GitHub Actions workflow (`.github/workflows/pages.yml`: `actions/upload-pages-artifact` on `site/`, `actions/deploy-pages`) on every push to `main` that touches `site/`. The user enables Pages → "GitHub Actions" once in the repository settings (one click; I cannot do it from here).
- URL: `https://viruxe.github.io/scavengesurvive-mta/`. Every link and asset path is relative, so a custom domain later is only a `CNAME` file.
- Images: optimised copies in `site/assets/` (WebP at 1600 px for scenes and places, about 150–300 KB each; item renders at 256 px WebP, about 15 KB). `docs/images` stays the archive; the site never links into the wiki's raw URLs, so it works offline and survives a wiki reorganisation.
- Budget: whole site under 25 MB, first view under 1.5 MB, no external script except the YouTube embeds (lazy, click-to-load).

## 5. Art direction ("extreme eye-candy", no stock assets)

- **Palette** from the logo: charcoal `#141414` / `#1f1f1f`, bone grey `#b9b9b9` for type, ember orange `#ff6a00` to `#ffb347` glow for accents, rust `#7a3b16` for dividers. Dark only (the game is dark; a light theme would fight every screenshot).
- **Type:** a condensed display face (Bebas Neue or Oswald, self-hosted WOFF2) for headlines, Inter for body, a monospace for numbers and keys (`F`, `N`, `H` key caps as in the HUD).
- **Motion:** canvas dust-and-embers in the hero (respects `prefers-reduced-motion`), scroll-driven reveals with IntersectionObserver, parallax on the hero and section backgrounds, counters that count, a "crack" reveal on the logo (SVG mask animation), hover tilt on slates and item cards, the map layers cross-fading. No scroll-jacking libraries; everything is under 30 KB of hand-written JS.
- **Texture:** film grain overlay, vignette, the rusted-metal header bars re-created in CSS gradients (nod to upstream, not copied), key-cap chips, dotted "survey" lines around numbers.
- **Responsive:** phone first, 16 px gutters, no horizontal scroll; the map and gallery become swipe strips.
- **Accessibility:** contrast AA on all text, focus rings, alt text on every image, reduced-motion kills the particle canvas and parallax.

## 7. Wiki improvements (the part that needs a decision)

The wiki is already strong: 65 hand-written pages, 323 generated item pages, maps, scenes, item renders, refreshed 2026-11-03. What it lacks, from the census:

- Pages for the newest features: **Driver's Dashboard**, **Car Batteries and Starters** (wear, EMP, draining), **Bobcat Salvage Parts** (the runbook's player-facing half), **Trailers and Towing** (the Airstream, native hitch), **Voice**, **Discord** (bridge and Rich Presence), **Languages** (the ten codes, `/lang`), **Joining the Server** (install MTA, requirements, downgrade note), **Changes from the Original** (the same census, wiki-flavoured), **Weapons Caches** (only mentioned in two pages), **Masks** (hats have a page, masks are inside Clothes).
- Screenshot slots on the pages that have none (only four pages embed in-game screenshots): the same `shot-*` ids as the site, as `<!-- shot:<id> -->` markers in the style of the existing `<!-- scene:hero -->`.
- Home page: a short "What changed" section and the hero scene slot filled with the site's key art once it exists.
- Sidebar: the new pages in their sections.

Blocker: this session cannot push to the wiki repository (the git proxy only allows `VIRUXE/scavengesurvive-mta`; `add_repo` refuses `.wiki`). Options:

- **A (recommended):** move the wiki source into `wiki/` in this repo and add a second Actions job that mirrors `wiki/` to the wiki repository on every push (the standard "github-wiki-action" pattern, needs no secret beyond `GITHUB_TOKEN` with `contents: write`). The wiki then versions with the code, `tools/wiki_tables.py --wiki wiki` runs in-repo, and I can write every page now. Cost: 45 MB of wiki images move into the main repo (or stay only in the wiki repo and the mirror job leaves `images/` untouched: I would do the latter).
- **B:** I write the new and changed pages under `site/wiki-staging/` in this branch with a one-line script that copies them into a local wiki clone; you run it and push the wiki from your machine.
- **C:** wiki untouched this round; the site only links to it.

## 8. Out of scope / later

- Live player count: needs a public JSON the server writes (the `dev` HTTP export or a tiny cron on the host). The hero has the slot and a `fetch` behind a config flag.
- Portuguese translation: the markup is built with `data-i18n` keys and a `lang/pt.json` stub so it is a translation job, not a rebuild; the first release ships English only unless you want PT now.
- A custom domain (`CNAME`).
